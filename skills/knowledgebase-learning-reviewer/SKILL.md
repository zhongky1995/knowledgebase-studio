# Knowledgebase Learning Reviewer

Use for a current teaching question or an explicitly requested learning review. Read the actual connected material from the target reader's starting point. Evaluate whether the sequence builds understanding, examples support the intended distinction, and important prerequisites appear before they are needed. A readable paragraph can still leave its promised mechanism unexplained.

The main author/editor owns the integrated product. Explain findings with actual passages and likely causes; question chapter responsibilities or examples when warranted. Suggest deletion, merging, moving or replacement as well as additions. Do not impose one lesson template or turn every reading task into an exercise. The editor decides how findings affect the whole.

For an overall progression question, use the architect's [structural method](../knowledgebase-architect/references/structure-method.md), actual reading order and connected full-text samples. Judge how understanding develops across the entry and transitions separately from whether individual chapters are sound. A heading-only overview cannot establish that an unread chapter explained or omitted a premise. The executor's `readingPath` preserves this scope and an overall judgment in the same review.

Read the content builder's [shared editorial method](../knowledgebase-content-builder/references/editorial-method.md). Turn the actual reader need into work using the text: explain a consequential relationship, compare reasonable paths or reason through changed conditions as relevant. Select the complete argument, including necessary adjacent prose, rather than isolated chapters asked to prove the whole book. User hypotheses may be challenged; the editor's restatement must not quietly redefine success. [Continuous comparisons](../knowledgebase-content-builder/references/editorial-examples.md) calibrate these choices. Use `references/novice-mental-model.md` under the content builder for a causal break in a system explanation.

Complete the reader work before giving an editorial verdict. Return the actual explanation, comparison or artifact, distinguishing text, valid inference and extra assumptions. Then assess what the argument supports and whether its development and emphasis serve the original purpose. At a stuck point, check the rest of the unit and the reading boundary before diagnosing omission; justified uncertainty is not automatically a defect. If a worked answer could hide an input gap, use the existing input-only trial. Inspect errors in the attempted work as well as the text. This is simulated reading, not evidence of human learning.

For operations, troubleshooting or teaching interactions, read `references/learning-activity-design.md`. A text walkthrough may be sufficient. Where an interaction is part of the product, maintain the existing shared activity manifest with actual feedback, recovery and accessible fallback. Respect the requested exercise/pressure policy.

A visual is useful when it carries a relationship, flow, comparison or change that prose does not carry well. Coordinate with the visual explainer while developing the content; it need not wait for an architecture stage. Judge the actual embedded asset, not the presence of a diagram requirement.

Record only the consequential teaching choices and findings in the existing editorial decision. Use a separate `learning-design.json` when the product's complexity or existing staged contract needs it; do not require a full lesson-by-lesson matrix for ordinary prose. Existing contracts keep their original validation when renewing a legacy stage. Reuse unit outcomes/prerequisites rather than repeating them.

Independent review, when needed, uses the controller's `references/independent-execution.md`. Its text-only reader cannot verify external sources merely because the manuscript quotes them; required source verification stays with the actual source review. Distinguish editor judgments, model walkthroughs and actual learner observations. Report scope and uncertainty; never invent learner outcomes.
